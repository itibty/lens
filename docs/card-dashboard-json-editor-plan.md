# 卡片与看板设计器 JSON 编辑实施计划

日期：2026-09-23

状态：待实施；本次仅形成计划。

## 1. 目标与范围

在卡片、看板设计页面各增加一个 `JSON` 按钮，通过一个 Dialog 查看、复制和录入当前配置。弹窗只有一个 JSON 编辑器，底部提供“取消”“确定”；确定后回填当前设计器，继续使用页面原有保存功能。

本期以现有持久化配置为基础，只增加编辑入口、必要的格式检查和状态转换。不建设新的配置协议或通用导入引擎。

范围：

- 卡片设计器：一个配置对象，包含元信息、`query`、`visual`，不拆成两个 Tab。
- 看板设计器：现有 `config_json` 对应的对象。
- 当前未保存修改的查看、复制、录入、回填和预览。
- 复用现有组件、权限、查询和保存流程。

本期不包含数据集 JSON 编辑、普通报表查看页入口、文件上传下载、依赖打包、跨环境迁移、资源复制、分支合并、配置历史或并发版本控制。JSON 确定不会创建或更新数据库记录。

## 3. 交互约定

### 3.1 入口与布局

- 卡片：在设计页工具栏中增加 `JSON` 按钮。
- 看板：在现有设计操作区增加 `JSON`，普通查看模式不展示。
- 仅具有对应配置权限时提供入口；页面加载、保存或应用配置期间禁用相关操作。
- Dialog 标题分别为“卡片 JSON”“看板 JSON”，采用现有大尺寸预设；编辑区滚动，小屏适配可用高度。
- 一个编辑器，不增加查看／编辑模式切换，不拆分查询与展示 Tab。
- 编辑器工具保留复制、格式化、全屏；不显示会造成额外提交入口的执行／保存工具。
- 底部按钮为“取消”“确定”。固定提示：**确定后应用到当前设计器，点击页面保存才会生效。**
- 看板补充简短说明：**仅包含看板布局与设置，卡片 ID 引用现有卡片。**

### 3.2 操作行为

| 操作 | 行为 |
| --- | --- |
| 打开 | 从当前设计器草稿生成持久化格式的 JSON，包含未保存修改；不重新查询数据库旧配置 |
| 编辑／格式化 | 仅修改弹窗文本，不联动设计器、不触发查询和保存 |
| 取消／关闭 | 丢弃本次弹窗文本，设计器草稿及原有未保存状态保持不变 |
| 确定成功 | 整体应用配置、关闭弹窗，按现有设计器流程更新预览 |
| 确定失败 | 保留文本与错误提示，弹窗保持打开，原设计器配置不被部分替换 |
| 页面保存 | 继续经过原有保存弹窗、校验、请求转换及接口 |
| 再次打开 | 从最新设计器状态重新生成 JSON，不恢复上次已取消的文本 |

点击遮罩不关闭，防止误触丢失输入；关闭按钮和 Esc 等价于取消，不增加二次确认。应用期间防止重复确定；若关闭或切换了当前资源，丢弃迟到的应用结果。

只查看或格式化不应改变页面 dirty 状态。确定时配置语义未变化，也不应把原本干净的页面标为未保存；已有未保存状态不能因此清除。JSON 应用成功后不能更新“上次已保存”基线。

## 4. JSON 内容

### 4.1 卡片：一个完整配置对象

采用设计器现有命名，形如：

```json
{
  "name": "营收趋势",
  "desc": "按月份汇总营收",
  "status": "EBL",
  "query": {
    "datasetId": "9101",
    "dimensions": [{ "field": "month" }],
    "metrics": [{ "field": "revenue", "agg": "SUM" }]
  },
  "visual": {
    "chartType": "bar",
    "showTitle": true
  }
}
```

此示例要求当前系统存在相应数据集与字段，不代表创建这些依赖。

- `name`、`status`、`query`、`visual` 为完整对象的固定部分；`desc` 可省略，省略表示清空描述。
- `query`、`visual` 均为对象，其字段沿用当前持久化配置；不展示转义字符串，不额外设计查询语言。
- `query.datasetId` 是数据集来源，`visual.chartType` 是图表类型来源；不在顶层重复这两个字段。
- `name`、`desc`、`status` 同步设计器和随后打开的保存弹窗。新卡片允许名称尚未填写，最终仍由原保存流程要求名称有效。
- 不包含 `id`、`updatedAt`、审计信息、预览数据、拖拽 `_uid`、加载状态等。当前资源身份和新建／编辑模式由所在页面决定。
- 现有草稿转换为规范化持久化内容时必须使用深副本，不因打开 JSON 而修改草稿。
- 保存仍由 `toVisCardSaveRequest` 将元信息映射为请求字段，并将 `query`、`visual` 序列化为 `queryJson`、`visualJson`。必要时提取其内部已有规范化逻辑供 JSON 导出共用，不复制一套保存规则。

数据流：

```text
可视化编辑 ─┐
           ├─ 当前卡片配置对象 ─ 原有请求转换 ─ 原有保存接口
JSON 编辑 ─┘
```

### 4.2 看板：直接使用 config_json

形如：

```json
{
  "widgets": [
    { "kind": "card", "cardId": "9201", "x": 0, "y": 0, "w": 12, "h": 8 }
  ],
  "autoRefreshSec": 60
}
```

- 支持现有 `widgets`、`filters`、`theme`、`cardRadius`、`autoRefreshSec`、`cardDisplayOverrides` 及当前编解码器能够保留的扩展字段。
- 平铺组、Tab 页、文本节点沿用现有结构，节点 ID 保留。
- `widgets` 必须明确提供，`[]` 表示清空布局；可选配置缺省按现有默认值处理。
- 不包含看板实体 ID、名称、描述、图标、所属分组、启停状态、角色授权、订阅或个人视图；这些不属于 `config_json`，继续在原入口编辑。
- 不包含卡片定义或数据集 SQL，不复制卡片、不转换引用 ID。
- 筛选器的已配置默认值属于 JSON；预览时临时选择的筛选值、Tab 状态、临时预览主题不写入配置。

卡片内容覆盖其可编辑元信息与两部分配置，看板内容限定为自身 `config_json`；二者统一交互，不强行统一存储结构。

## 5. 必要检查与回填规则

### 5.1 检查边界

“不做深度处理”指不自动迁移格式、不创建依赖、不推断字段映射，也不另建一套完整业务校验引擎。

录入时仍需进行最低限度的检查：

1. JSON 语法合法，根节点为对象；拒绝 `null`、数组和标量。
2. 必需对象、集合及其成员结构正确，例如 `query`、`visual`、`widgets`、筛选条件数组；防止回填后 `.map` 等操作直接失败。
3. 图表类型、状态、布局节点类型等采用项目已支持的值；所有资源 ID 使用字符串，避免大整数精度损失。
4. 对当前页面不可编辑的身份字段明确提示，不允许粘贴 `id` 改变保存目标。
5. 输入错误指出字段路径，例如 `widgets[0].cardId`；不清空输入、不静默跳过错误节点。

结构正确但尚未完成的业务配置可以回填，随后沿用设计器的字段与图表校验；配置无效时不得执行查询或保存，旧预览不能冒充新配置的结果。对无法支持且会被转换过程直接丢弃的输入，应明确报错，不默默删除用户输入。

JSON 只作为配置数据解析，不执行输入代码。富文本沿用现有预览与保存清洗规则。

### 5.2 卡片回填

- 先解析为独立候选对象，保持当前卡片 ID、更新时间和路由不变。
- 以一次整体替换应用候选配置，不逐字段修改触发中间状态。
- 增加最小的“正在应用 JSON”保护或复用加载流程：暂缓数据集变更、图表切换与字段依赖清理的 watcher，避免把刚录入的指标、筛选、明细和样式清空。
- 需要数据集时加载相应字段，使用请求序号防止旧响应覆盖新状态；候选引用的数据集读取失败时保留原草稿及弹窗内容。未选择数据集的未完成草稿仍按原设计器处理。
- 回填后补齐编辑器所需的临时 UID，关闭旧明细、重置旧预览，待字段准备完毕再按现有规则预览与提示。
- 整体应用不会额外弹出“切换数据集将清空配置”的确认；本次确定已经表达整体替换意图。
- 保存、另存为继续使用原逻辑，JSON 自身不能指定覆盖另一张卡片。

### 5.3 看板回填

- 先检查原始输入，再进入现有编解码；不能直接以容错 `parseDashConfig`／`sanitizeWidgets` 判断输入有效。
- 从候选布局提取实际卡片 ID，按候选成员读取所需卡片；不能用旧看板成员列表过滤新输入，否则新增引用会被误删。
- 详情获取失败不能解释为卡片已删除。必要卡片读取失败时保留原看板和弹窗文本，明确提示重试或修正引用，不应用残缺结果。
- 已存在但禁用的卡片按现有规则保留禁用状态，不能静默移除。
- 准备成功后整体替换 widgets、cardMap、筛选定义、主题、刷新周期、局部显示覆盖及扩展字段。
- 同步筛选默认值、重置临时主题及必要的运行状态，再刷新预览；节点标识和共享卡片 ID 保持不变。
- 看板保存仍使用 `saveDashboard`，成员索引继续按现有后端逻辑维护，不在 JSON 弹窗单独写关联表。

两类编辑器都只在当前对象仍匹配、弹窗应用仍有效时接收异步结果。失败后的恢复要包含运行状态，不留下半套新配置。

## 6. 实施步骤

1. **配置转换与检查。** 在卡片、看板目录分别增加小型 JSON codec／检查模块，明确输入对象、导出内容和错误格式。复用已有持久化转换，保持模块只处理本功能所需规则。
2. **共用弹窗。** 在 `views/vis/shared/` 增加 `ConfigJsonDialog.vue`，复用 `CustomDialog` 和 `CodemirrorEditor`。负责临时文本、复制／格式化、错误显示和异步确认状态；业务回填交给调用页面。
3. **卡片接入。** 增加工具栏入口、导出草稿与原子回填逻辑，处理数据集与类型 watcher、字段请求和未保存状态。
4. **看板接入。** 扩展 `DashToolsMenu`／`DashFilterBar` 事件，在 `DashDesigner` 接入；处理新卡片引用、读取失败和基线保持。
5. **验证与文档。** 补充关键数据完整性用例，执行必要检查与浏览器验收，最后在本文件记录实际实现和验证结果。

优先保持前端改动；本期不安排接口、DDL 或生成 API 变更。若实施中发现现有保存接口缺少本功能必需的校验，记录具体缺口再收敛调整，不扩展为通用配置平台。

## 7. 验收与检查

### 7.1 自动化验证重点

测试聚焦配置丢失、错误覆盖和异步竞争，不为单纯按钮展示编写镜像测试。

- 已支持配置导出再录入，最终保存请求的配置语义保持一致；内部 UID 和实体身份不会混入 JSON。
- 取消、语法错误、错误集合类型、非法身份字段不会修改原草稿。
- 卡片同时更改数据集与图表配置，watcher 不会清空录入内容；字段加载失败与过期响应不留下部分更新。
- 看板新增卡片引用不受旧成员索引过滤；卡片请求失败不删除布局，Tab、文本、筛选、局部覆盖与扩展配置正确保留。
- 无变化确定不改变 dirty；有效变更产生 dirty，保存基线只在实际保存成功时更新。
- JSON 确定没有调用卡片／看板写接口；后续保存和另存为的目标 ID、序列化内容正确。

前端实现后，从 `frontend/` 执行：

```sh
pnpm lint
pnpm type-check
pnpm test <本次新增或受影响的测试文件>
```

根据实际修改选择 JSON codec、卡片回填、看板编解码／保存的相关测试。只有实际涉及后端修改时才增加 `mvn test`。本次纯文档交付不运行应用测试。

### 7.2 浏览器验收

1. 两个设计页均为一个按钮、一个 Dialog、一个编辑器；权限和禁用状态符合原设计页。
2. 先修改可视化配置，再打开 JSON，能看到未保存修改；只查看、取消、Esc 不丢失原草稿。
3. 录入合法内容后确定，预览更新，但数据库尚未改变；点击页面保存并重开后结果一致。
4. 验证普通图、透视表、静态卡的 query／visual；更换数据集与图表类型时保留有效输入。
5. 验证看板平铺组、Tab、文本、筛选默认值、主题及局部标题；修改卡片引用后能正确显示新成员。
6. 输入非法 JSON、错误类型、无效引用和网络失败时留在弹窗，保留输入与原配置，不出现空白覆盖。
7. 应用过程中快速关闭／切换资源、重复点击，不发生过期回填或重复请求提交。
8. 复制、格式化、全屏、长 JSON 滚动及较窄窗口下的按钮与错误提示可用。

## 8. 完成标准

卡片和看板设计器都能通过同一个 JSON 编辑入口查看、复制和录入当前配置；有效输入完整回填，错误输入不破坏草稿；真正持久化统一经过既有保存流程。实施完成后补充实际检查结果，并将文档状态更新为已实施。
