# Lens 个人视图保存 Tab

日期：2026-09-16

状态：已实现

目标：个人视图、复制链接和订阅同时保存筛选与 Tab 选择。

## 1. 已确定的产品规则

**能恢复的恢复，找不到的使用当前报表缺省值。**

- Tab 找不到，使用所在分组的默认 Tab；分组不存在，忽略该分组的旧选择。
- 筛选器不存在，忽略旧值；筛选绑定或值不再兼容，使用当前筛选器的默认值。
- 新增的 Tab 分组、筛选器使用当前报表默认值；没有默认筛选值时使用空值。
- 个人视图、链接、订阅预览、自动发送和邮件回看采用同一套规则。
- 这些配置变化正常恢复，不弹提示，不要求修复，不自动暂停订阅，也不因此显示“未保存”。

本方案替代上一期设计中“绑定变化使视图失效、订阅暂停”的兼容策略；旧文档仍记录已交付实现，本次已统一调整。

本期只增加 Tab 状态及上述缺省恢复。图例选择以后再评估；下钻、联动重新考虑，暂不排期，旧草案不作为实施依据。

## 2. 用户操作

示例：用户筛选“华东”，将“经营指标”分组切到“利润”，保存为“华东经营”。

| 操作 | 结果 |
| --- | --- |
| 切换筛选或 Tab | 修改当前查看状态，不自动覆盖已保存视图 |
| 保存／更新视图 | 同时保存当前已应用的筛选和各分组的 Tab |
| 切换个人视图 | 一次性恢复筛选和 Tab，再查询对应卡片 |
| 使用报表默认 | 筛选恢复当前公共默认，各分组恢复默认 Tab |
| 设置个人默认 | 下次从普通报表入口进入时恢复整份视图 |
| 复制视图链接 | 对方打开时恢复相同筛选和 Tab，并按其自身权限查询 |
| 新建订阅，选择当前视图 | 复制当时的筛选与 Tab，后续修改个人视图不联动修改订阅 |
| 刷新数据 | 保留当前筛选与 Tab |

沿用现有保存、切换和订阅入口，不增加页面、开关或常驻说明。名称输入框仍只填写视图名称。

必要文案调整：

- “复制筛选链接”改为“复制视图链接”。
- 订阅“当前筛选”改为“当前视图”，“已保存的筛选”改为“已保存的内容”。
- 订阅内容摘要沿用现有位置，按需加入“经营指标：利润”等短项。

## 3. 缺省恢复的具体含义

### Tab

当前没有独立的默认 Tab 配置，本期继续使用**当前分组顺序中的第一项**，不增加默认项设置。

| 配置变化 | 恢复行为 |
| --- | --- |
| 改 Tab 标题、分组名称或 Tab 顺序 | 按标识恢复原选中的卡片 |
| 选中卡片被删除或移出原分组 | 原分组选择当前默认 Tab |
| 分组删除、解散或由 Tab 改为平铺 | 忽略该分组保存的选择，按当前布局显示 |
| 新增 Tab 分组 | 使用新分组的默认 Tab |
| 分组没有任何 Tab | 显示现有空态 |

卡片详情请求暂时失败、卡片被禁用或数据查询失败，不等于 Tab 不存在。保留选中项并展示现有不可用／错误状态，不能偷偷切到另一张有数据的卡片。

### 筛选

- 以当前报表的筛选定义为准，逐项恢复；一个旧筛选失效不能清空其他仍有效的筛选。
- 已删除的筛选丢弃；新增筛选补默认值。
- 同一筛选 ID 的字段、数据集、类型或用途发生变化，旧值作废，补当前默认值。
- 筛选值格式与当前控件不兼容时补默认值；默认值本身无法使用时按控件空值处理。
- **显式清空仍然有效**，不能用默认值重新填回。只有缺失或不兼容才使用缺省。
- 合法筛选查不到业务数据时保留空结果。异步选项只返回部分候选，不凭“当前候选列表里没有”认定保存值失效。
- 筛选配置已删除的字段不再用于生成查询条件；卡片本身存在查询配置错误时继续呈现查询失败。

缺省恢复针对保存状态与报表配置的兼容性。无权限、请求失败、整体状态 JSON 损坏等继续走现有错误处理，不用默认状态掩盖失败。

## 4. 状态模型与兼容

```json
{
  "schemaVersion": 2,
  "filters": {
    "f-region": { "value": ["华东"] }
  },
  "tabs": {
    "g-operating": { "activeCardId": "9208" }
  }
}
```

- Tab 使用 **分组 ID + 卡片 ID**；不保存标题、顺序或 page ID。当前编辑分组成员、顺序时可能重建 page ID。
- 保存当前所有 Tab 分组的实际选择，包括选中默认项的分组。这样调整顺序后，已保存视图仍选择原卡片；只有原卡片不在该分组时才缺省。
- 筛选只保存已应用值，不包含筛选弹层内尚未确认的草稿。
- 读取版本 1 时，保留筛选并补当前默认 Tab；显式保存时写版本 2。普通读取不更新数据库或 revision。
- 标准化后按固定键顺序序列化；用标准化结果建立比较基准，避免兼容恢复造成虚假的“未保存”。用户主动改变筛选或 Tab 后才进入未保存状态。
- 现有 `state_json` 可直接承载新状态，`bindings_json` 继续记录筛选语义签名，用于识别哪些旧值应当缺省。无需新增表或字段。
- 保留绑定检查，只将配置不兼容的处理改为逐项缺省；不能通过删除签名检查，把旧字段的值直接套到新字段上。

## 5. 链接与状态来源

新增 `vs` 查询参数，使用现有编码工具承载 `{ state, filterBindings }`：`state` 是完整的版本 2 状态，`filterBindings` 是解析服务返回的筛选绑定签名。新链接只输出 `vs`，旧 `f` 链接继续可读。

绑定签名用于识别“同一筛选 ID 已换字段”等配置变化，不作为授权依据。服务端始终以当前定义校验；旧 `f` 链接没有历史签名，只能按当前定义核验值的格式和类型。

打开时按以下顺序选取一个来源：

1. `subscriptionRunId` 对应的运行状态。
2. `vs` 完整视图状态。
3. 旧 `f` 筛选状态，Tab 使用当前报表默认。
4. `viewId` 指定的个人视图。
5. 个人默认视图。
6. 报表公共默认。

来源之间不混合。缺失项从公共默认补齐，不从另一个个人视图取值。

- `vs` 即使包含空筛选、空 Tab 对象，也表示显式选择公共缺省，不能被个人默认覆盖。
- 初始化时先恢复，再开启 URL 同步；筛选和 Tab 一起通过 `history.replaceState` 写入，不逐次增加浏览器历史。
- 普通查看页统一由一处写 URL，去掉旧 `f` 写入器与新写入器并存的情况；写新状态时移除 `f` 和已被快照替代的 `viewId`。
- 订阅运行入口保留运行 ID，以运行状态为准；不将 URL 中另带的 `vs` 或 `f` 覆盖进运行状态。
- 独立预览继续传递当前完整状态；复制链接和重新加载都能恢复 Tab，包括没有筛选器的报表。

## 6. 订阅与截图

### 保存和运行

- 新建或明确更新订阅内容时，复制筛选与 Tab 的完整状态；选择报表默认时也保存当时解析出的完整状态。
- 仅修改发送时间、名称，或选择保留原内容时，不重写原快照。
- 旧订阅没有 Tab 状态，继续使用当前默认 Tab；不批量修改旧记录。
- 入队时统一解析缺省并复制到运行记录，重试沿用该记录及已有日期基准。
- 如果执行或回看时配置又发生变化，仍使用同一套缺省规则，不因缺少 Tab 或旧筛选而暂停／失败。
- 这是查看状态快照，查询继续使用当前报表配置和实时数据，不新增报表配置版本或历史数据存档。
- 摘要从实际解析结果生成，不继续显示已经被丢弃的旧筛选或旧 Tab 名称。

### 截图范围

- 先恢复全部筛选与 Tab，再挂载并查询对应卡片，避免先查询／截取默认 Tab。
- 每个 Tab 分组只截图当前选中项；根卡片和平铺分组按原行为截图，不增加“导出全部 Tab”。
- 截图期间固定筛选和 Tab 选择，完成或失败后恢复交互。
- 查询等待及完成检查只覆盖本次截图实际展示的卡片；离开的 Tab 的迟到请求不能阻塞截图或覆盖状态。
- 所选卡片真正查询失败，仍沿用已有截图失败处理；配置项找不到并已正常缺省，不视为失败。
- 邮件链接按运行状态恢复同样的选择，配置变化时同样缺省。

## 7. 实施落点

| 部分 | 改动 |
| --- | --- |
| `dashboardViewState.ts` | 增加版本 2、Tab 状态、版本 1 兼容和稳定序列化 |
| `DashboardViewStateService` | 统一解析筛选与 Tab；逐项缺省；校验分组成员关系；摘要基于有效结果 |
| `PersonalReportService` | 读取、保存、设默认共用解析规则；修改名称等操作保留原绑定，防止绕开缺省判断 |
| 视图解析 DTO | 返回当前绑定签名，支持接收链接携带的签名；输入只用于兼容判断，不能替代当前报表定义 |
| `useDashboardViewState.ts` | 持有完整查看状态，原子恢复，统一保存和未保存比较 |
| `DashViewer` / `DashGrid` / `DashGroupTile` | 查看态传递受控 Tab 选择及变更事件；设计器保留本地选择，不污染个人视图或公共布局 |
| URL 同步模块 | 完整状态 `vs` 读写、旧 `f` 兼容、切换报表时清理旧状态 |
| 订阅表单和运行服务 | 复用完整状态，内容摘要和文案调整，旧内容兼容 |
| 查询追踪与截图 | 切换 Tab 后清理旧卡片状态，截图只等待当前展示卡片 |

Tab 目录以当前看板配置和后端卡片成员关系为准，不以某次详情请求成功与否决定成员是否存在。后端只接受该分组真实成员；无效 ID 走缺省，不据此查询任意卡片。

本期不新增通用状态框架；复用现有 composable、状态解析服务和订阅链路。API 如需修改公开 DTO 或说明，按项目约定重新生成客户端。

## 8. 实施顺序与验收

1. 完成状态版本、Tab 目录与统一缺省解析，先验证兼容语义。
2. 接入查看态 Tab、保存／切换视图、URL，验证普通用户操作。
3. 接入订阅和截图，完成端到端验收。

必须覆盖：

- 多个 Tab 分组各自保存选择；没有筛选器、没有 Tab、空分组均能正常使用。
- 保存、切换、默认视图、刷新、复制链接、独立预览恢复一致。
- Tab 重命名和重排不改变保存选择；删除、移出、分组模式改变后正常缺省。
- 旧筛选删除、绑定改变、值不兼容只影响对应项；新增项用默认值；显式清空不被覆盖。
- 自动缺省不产生提示、未保存状态或订阅暂停；旧版本读取不改库。
- 快速切换视图、Tab、报表时，旧响应不覆盖新状态；数据刷新不重置 Tab。
- 订阅保存后再修改个人视图，不改变已有订阅；旧订阅和旧链接可继续使用。
- 同一报表两个订阅选择不同 Tab，得到不同截图；只修改计划不重写内容。
- 未选中 Tab 的慢请求或失败不阻塞当前截图；选中卡片失败仍按现有规则处理。
- 缺省解析、运行摘要、截图和邮件链接结果一致；现有用户权限检查不变。

验证范围：前端 lint、类型检查、构建及状态恢复测试；后端单元测试、临时 MySQL 中的视图／订阅保存与缺省恢复、Chrome 截图测试；浏览器验证保存与切换视图、刷新恢复、失效链接缺省、实际截屏和订阅内容摘要。未执行真实邮件发送，无表结构变更。
