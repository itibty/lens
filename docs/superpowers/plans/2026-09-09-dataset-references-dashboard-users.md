# 数据集关联与看板相关用户实施计划

日期：2026-09-09

状态：功能已实现；后端测试、前端 lint、类型检查与生产构建通过。浏览器实测待本地账号登录。

## 目标与界面约定

| 入口 | 弹窗标题 | Tab | 操作 |
| --- | --- | --- | --- |
| 数据集列表操作列：查看关联 | 「名称」的关联 | 关联卡片、关联看板 | 只读；按目标页面权限提供跳转 |
| 看板树具体看板节点更多菜单：用户 | 「名称」的相关用户 | 用户、授权角色 | 用户只读；授权角色行提供小尺寸 primary 链接“解除关联” |

- “相关用户”默认打开用户 Tab；无用户查询权限但有角色查询权限时打开授权角色 Tab。
- 看板分组不增加此操作。打开弹窗不切换选中看板、不触发设计器保存、不丢失未保存内容。
- 两个弹窗分别封装为业务组件，页面只负责入口和传入对象 ID、名称。
- 复用 `CustomDialog`（标题、尺寸、关闭、滚动）、`showConfirm`、`showToast`、`v-spinner`。
- 内部使用 `el-tabs`、`el-table`、`el-tag`，需要分页时使用 `el-pagination`。沿用卡片关联弹窗的实现方式。
- 不使用 `ListTable`：其自动列与前端分页不适合这里大量自定义单元格和用户后端分页；不为本需求修改通用表格组件。
- 不使用 `TableForm`：这里是服务端关联查询与即时解除操作，没有可编辑行表单。
- 每个 Tab 独立维护加载、失败与空态；失败可重试，不能把请求失败显示成“暂无关联”。
- 切换对象、关闭重开时清空旧状态并隔离过期响应；解除操作绑定点击时的看板和角色 ID。

## 关联数据口径

### 数据集

1. 卡片：复用 `GET /datasets/cards?datasetId=...`，以 `vis_card.dataset_id` 为准，排除已删除卡片，保留禁用卡片。
2. 看板卡片引用：通过 `vis_dashboard_card` 关联卡片与看板。现有看板保存流程已递归抽取分组中的卡片并维护该表。
3. 过滤器绑定：解析已保存 `config_json.filters[].datasetId`，包含筛选条件和参数两种用途。
4. 过滤器选项源：解析 `filters[].options.datasetId`，仅在 `options.source = dataset` 时成立。
5. 看板按 ID 去重，每行汇总全部关联来源及明细；排除已删除看板，保留禁用看板。重复卡片引用不重复计数。
6. 过滤器绑定即使暂时没有对应卡片，也展示为配置关联；只统计已保存配置，不读取浏览器草稿。
7. 卡片列：名称、状态；看板列：名称、所属分组、关联内容、状态。名称按权限提供跳转，关联内容合并显示来源标签与卡片名或过滤器名称/字段。
8. 返回 ID 始终为字符串。解析 JSON 时精确比较 ID，不用字符串模糊匹配；兼容历史字符串/数字 ID，处理缺失字段。
9. 补齐数据集删除检查：过滤器直接引用或作为选项源时也阻止删除。前端提示与后端校验共用同一查询口径；后端始终重新检查。
10. 本次不扩展更换数据源时的影响提示，不做自动清理过滤器配置。

### 看板相关用户

1. 授权角色：`sys_role_dashboard → sys_role`，排除已删除角色，保留禁用角色。展示角色名称、编码、状态、解除关联操作。
2. 用户：经上述角色关联 `sys_user_role → sys_user`；排除已删除用户，保留禁用用户。按用户 ID 去重，每个用户保留全部关联角色来源。
3. 用户列：用户名、姓名、账号状态、关联角色。关联角色单元格显示角色状态、授权有效期与“生效中／未生效／已过期”。
4. 有效期边界与 `SysUserMapper` 保持一致：开始时间为空或 <= now，结束时间为空或 >= now；使用服务端统一时间计算。
5. 有效期标签描述用户角色配置，不声称当前登录会话已有访问权限。看板/上级分组禁用、登录时角色快照均可能影响实际访问。
6. 仅展示通过角色分配关联的用户，不将具有设计权限的额外访问者混入列表。界面不添加额外技术说明。
7. 用户列表后端分页，以去重用户分页后批量补齐角色来源；支持用户名/姓名搜索，分页 total 是去重后的用户数。
8. 授权角色列表一次返回精简数据；数据集关联列表沿用 `ListResponse`，弹窗需要时做本地分页。计数来自完整列表或分页 total，不以当前页行数代替。
9. 解除操作仅删除指定 `dashboardId + roleId` 关系；不删除角色、用户角色关联或该角色的其他看板。
10. 同一用户通过其他角色仍关联时继续保留。操作成功后刷新授权角色与用户列表，处理最后一页变空的情况。
11. 确认提示明确只撤销通过该角色的访问来源；沿用 `PermissionTokenService.invalidateRoleUsers`，相关用户登录态失效，需重新登录。

## 权限约定

| 能力 | 后端权限 | 前端展示 |
| --- | --- | --- |
| 数据集查看关联 | `vis:dataset:conf` | 数据集配置用户可见；跳转另查卡片/看板页面权限 |
| 看板授权角色查询 | `sys:role:query` | 看板管理入口下按角色查询权限显示 Tab |
| 看板相关用户查询 | `sys:user:query` | 看板管理入口下按用户查询权限显示 Tab；只返回必要的来源角色信息 |
| 解除看板角色关联 | `sys:role:write` | 在授权角色 Tab 中按角色写权限显示操作 |

- “相关用户”入口要求看板管理权限，且至少有用户或角色查询权限；无权限的 Tab 不请求接口、不展示计数。
- 系统关联接口分别沿用上述系统权限，与现有角色配置看板的权限保持一致；不因拥有看板设计权限就授予角色写权限。
- 注意当前 `@Permission({ ... })` 是任一满足（OR），不能用它表达“同时拥有多个权限”。
- 查询与解除均校验看板存在且未删除；接口只返回精简 DTO，不直接返回包含密码等字段的用户实体。

## 后端接口与职责

| 接口（拟定） | operationId | 响应/用途 |
| --- | --- | --- |
| 现有 `GET /datasets/cards` | `listDatasetCards` | 复用关联卡片列表 |
| 新增 `GET /datasets/dashboards?datasetId=...` | `listDatasetDashboards` | `ListResponse`；看板信息、来源类型集合、卡片/过滤器明细 |
| 新增 `GET /sys/dashboard-relations/roles?dashboardId=...` | `listDashboardRoles` | `ListResponse`；授权角色 |
| 新增 `POST /sys/dashboard-relations/users/query` | `queryDashboardUsers` | 请求含 dashboardId、keyword、page；返回 `PageResponse` |
| 新增 `POST /sys/dashboard-relations/unlink-role` | `unlinkDashboardRole` | 请求含 dashboardId、roleId；幂等解除 |

- 新建 `DatasetReferenceService` 统一关联查询与删除校验，避免前后端各自实现依赖判断。`DatasetAdminService` 调用该服务。
- 扩展 `VisDashFilters` 或增加同目录解析类，提供纯配置关联提取；直接引用与选项源独立收集。
- 首版不新增表：卡片链路使用现有索引，过滤器链路由服务端分批读取未删除看板的 ID、名称、分组、状态、配置并解析，最终合并结果。不要逐看板/逐卡片查询形成 N+1。
- 配置无法解析时应记录并明确返回查询失败；删除检查不得把解析异常当成无引用后放行。
- 新建系统侧 `DashboardRelationController`、`DashboardRelationService` 与精简 DTO，查询使用批量关联或专用 Mapper SQL。
- 解除在事务内按双 ID 精确删除，实际删除成功后触发既有权限失效流程；已解除重复请求返回成功且不重复触发失效。
- 不复用“查询角色所有看板 → 前端删一项 → resetDashboards”流程，避免覆盖其他并发授权变更。
- 现有数据库结构足够；若真实数据量使 JSON 解析成为瓶颈，再单独评估引用索引，不在首版加入索引同步和历史回填。

## 实施顺序

1. **完成后端数据集关联能力。** 新建关联查询服务/DTO，扩展过滤器解析，接入 DatasetController，补齐 DatasetAdminService.delete 的引用校验与测试。
2. **完成后端看板用户能力。** 添加系统侧 Controller/Service/DTO/Mapper 查询，完成用户去重分页、角色有效期、精确解除及权限失效测试。
3. **生成接口客户端。** 启动本次修改后的后端，在 frontend 执行 `pnpm generate-api`，核对 admin/vis 分组及字符串 ID 类型；不手改生成文件。
4. **新增数据集关联弹窗。** 创建 `frontend/src/views/ds/components/DatasetRelationsDialog.vue`，在 `ds/index.vue` 增加入口并复用新依赖口径完善删除提示。
5. **新增看板相关用户弹窗。** 创建 `frontend/src/views/vis/dashboards/components/DashboardUsersDialog.vue`；修改 `dashManage.ts` 的命令类型、`DashExplorerTree.vue` 菜单与 `dashboards/index.vue` 接入逻辑。
6. **联调与检查。** 完成下面的自动检查及人工验收，记录接口生成和验证结果。用户已追加授权：复查工作区并适当优化后提交、推送 main。

## 验证与验收

- 后端：在 backend 使用 JDK 21 执行 `mvn test`。
- 前端：在 frontend 执行 `pnpm lint`、`pnpm type-check`；若新增纯数据转换逻辑，添加对应 Vitest 测试并运行，不为简单弹窗包装额外搭建测试设施。
- 数据集用例：无引用、仅卡片、仅过滤器绑定、仅选项源、三种来源并存、分组卡片、同看板多卡片去重、禁用/删除状态、历史 ID 格式、异常配置。
- 删除用例：仅过滤器引用也不能删除；前端检查后新增引用时后端仍拦截；无引用可正常删除。
- 用户用例：单角色、多角色同人去重、分页不切断角色来源、无期限/单边期限/未开始/已过期/边界时刻、禁用角色或账号、已删除对象排除。
- 解除用例：只删指定关系、保留其他角色/看板关联、重复请求幂等、多来源用户仍保留、登录态失效、无写权限返回 403。
- 界面用例：默认用户 Tab、权限受限 Tab、空态/加载/失败重试、快速切换对象无串数据、长名称和多角色内容可读、窄窗口滚动、用户搜索与分页、解除后末页回退。
- 看板设计器存在未保存修改时，对树中任意看板打开相关用户弹窗，当前编辑内容与选择保持完整。

## 当前范围

交付两个业务弹窗、四个新增接口、数据集删除依赖检查补齐及必要验证。暂不增加授权入口、直接用户授权、分组批量授权操作、关联图谱、导出、通用弹窗/表格重构。
