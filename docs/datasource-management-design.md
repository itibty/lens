# 数据源管理

日期：2026-09-17
状态：已实现并验证

后续已增加 StarRocks，连接方式、兼容处理与最新测试结果见 [StarRocks 接入方案](starrocks-datasource-design.md)。下文保留首次 MySQL/PostgreSQL 迭代的范围与验证记录。

## 目标与范围

让维护人员通过页面完成数据库接入、连接修改、测试和停用。沿用数据源 → 数据集 → 卡片 → 看板关系；支持现有 MySQL 与 PostgreSQL。PostgreSQL 验证配置、驱动、方言与自动化测试，不要求真实数据库联调。

本期提供一个列表页、一个编辑弹窗、一个引用弹窗。连接信息继续使用 JDBC URL。暂不增加其他数据库类型、跨源查询、驱动上传、定时健康监控或连接池调参页面。

## 页面

- 后台导航增加“数据源”，位于数据集之后。
- 列表提供名称搜索、类型／状态筛选；列为名称、类型、连接地址、状态、数据集数量、操作。
- 常用操作为编辑、测试连接；More 收纳启用／禁用和删除。
- 编辑弹窗包含名称、类型、JDBC URL、用户名、密码；MySQL／PostgreSQL 提供对应地址示例。底部为测试连接、取消、保存。
- 编辑已有连接默认保留密码，只有选择“修改密码”才提交新密码；明确修改为空表示使用空密码。详情不回传密码。
- 测试结果展示成功／失败及耗时，修改连接字段后清除旧结果。测试只检查连接，不写配置，不替换正式连接。列表结果仅代表本次测试，不作为持续在线状态。
- 点击数据集数量打开引用列表；有数据集配置权限时可跳转编辑。

## 行为规则

1. 新增默认启用；保存连接信息时验证连接，失败保留原记录和连接池。仅修改名称不重复测试连接；注册表沿用名称寻址，改名后在下次查询重建连接池。
2. 数据源类型与 JDBC URL 必须一致；凭据通过独立字段传递，URL 不接受用户名／密码。支持常见编码、时区、SSL 和 PostgreSQL schema 参数；驱动超时由服务端固定，禁止自定义驱动类、连接工厂等参数。测试与连接建立设置超时，返回错误经过脱敏。
3. 有引用时修改连接信息或禁用需要确认，服务端重新统计引用数量；普通名称修改不提示。启用前验证连接。
4. 删除采用现有软删除方式；任何未删除数据集（含禁用数据集）引用时拒绝删除。
5. 已禁用数据源不出现在新建数据集选项中；现有数据集可保留原绑定并编辑其他信息。禁用后已有查询继续按数据源不可用处理。
6. 数据源删除／禁用与数据集绑定在事务内锁定同一数据源记录，防止引用检查与新增绑定并发穿透。
7. 管理权限为 `vis:datasource:conf`。数据集配置人员保留选择数据源与读取表结构权限，不获得连接凭据或连接修改权限。

## 实现

- 数据源管理使用独立 Controller、专用请求与响应 DTO；沿用 `vis_datasource`，不新增表。
- 新增分页查询、详情、测试、引用、启停、删除接口，保存接口改为明确字段白名单。
- 连接池按数据源隔离锁，网络连接不占用全局锁。保存先验证，事务提交后淘汰旧连接池，后续查询按最新配置延迟建立连接；回滚不改变已有池。
- 页面和服务端都对重复提交、加载失败及取消保留状态作处理。
- 原始 `schema.sql` 增加菜单和权限及管理员授权；直接同步本地数据库，不维护增量脚本，不重建本地应用表。
- OpenAPI 客户端从运行中的后端重新生成。
